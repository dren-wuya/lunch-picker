# 午餐随机选择器

> 开发状态（2026-09-22）：已有功能闭环保持不变；独立`codex/`分支已完成午餐签卡视觉改版代码，36项本地测试及48条目录校验通过。PR复审已补验内置浏览器布局与主要交互，并修复Windows换行导致的测试误报；真实键盘、原生文件选择器和系统减少动态偏好仍待人工验收。9月8日验证仅属于旧界面。有效目录仍为38家，三项餐厅证据缺口经补查仍未解决。产品边界以 [SPEC.md](SPEC.md) 为准，交付与验证边界见 [HANDOFF.md](HANDOFF.md)。

一个面向上海陆家嘴中心 L+MALL 泰康大厦工作日午餐的手机优先静态网页。第一版不需要账号、后端或构建步骤，所有历史和设置都保存在当前浏览器中。

当前“说明”页公开随机机制、目录边界和共享目录与个人叠加层合成后的有效餐厅目录。页面不展示图片、地图或推荐菜；有来源时仅提供公开资料入口。DOM 展示与事件已集中在 `js/view.mjs`，业务 controller 和持久化位于 `js/app.mjs`，纯规则与数据契约位于 `js/core.mjs`。第一版暂缓反馈功能。

已确认的完整产品边界见 [SPEC.md](SPEC.md)。

## 本地运行

浏览器不能稳定地从 `file://` 地址读取默认 JSON，因此请在仓库目录启动任意静态文件服务器。例如：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。

手工记录中输入名称后，只有点击候选才会关联正式餐厅；直接保存会保留输入原文，并可随后加入本地待入库。数据页可批量整理名称、维护个人随机池及设置忌口。共享目录更新不会自动改写既有记录，待入库名称始终不参与随机。

餐厅数据PR通过GitHub Actions运行同一个校验脚本，检查JSON可解析、唯一ID、名称／范围／文字位置和副范围1–8分钟步行时间，并复用运行时对可选字段的格式校验。检查通过不代表现实事实已经核实，仍需人工审核范围、营业与午间适用性；工作流不自动合并或部署。该工作流仅由PR触发，直接推送main不会运行这项校验。2026-09-22本地校验48条目录通过；不据此声称已通过线上Actions。

## 当前实现的数据

- 共享默认目录位于 `data/restaurants.json`；当前48条记录，有效目录为32家主范围和6家副范围餐厅，其中LG20家，另保留10条停用记录。每次启动都读取部署版目录，再叠加当前浏览器的个人新增与隐藏项。2026-09-10完成保留6家副范围的本店资料和固定泰康保险大厦起点步行导航核验，修正地址并用独立ID收录阿祥嫂和张杨路裕兴记；旧永和、原址未能核实的裕兴记以及明确闭店的付小姐和西贝停用；LG及其他楼层的完整性仍未确认，见 [目录核查](data/lg-review-2026-09-07.md)。
- 参考人均和副范围步行时间是公开信息基础上的近似值，不是实时承诺；默认列表核验日期为 2026-08-27。
- 当前数据可以保留 `recommended_dishes`，但该字段可缺失，页面不展示，也不把它作为入库条件。
- 网页只导入导出一个 `lunch-picker-backup.json` 个人备份；它包含设置、忌口偏好、个人叠加层、待入库名称和历史，不复制或覆盖共享目录。
- 新状态写入 `lunch-picker.state.v2`。没有有效 v2 但存在有效 v1 时会迁移设置、历史和个人额外餐厅；旧 `lunch-picker.state.v1` 不会自动删除。
- 个人历史只存在浏览器本地；不要把个人导出文件提交到公开仓库。
