# 午餐随机选择器

> 开发状态（2026-09-08）：已实现 v2 个人状态与迁移、单一个人备份、自由文字及别名候选、单个／批量待入库、个人新增／隐藏恢复、忌口设置和餐厅PR校验；36项本地测试通过，并已在内置浏览器验证主要交互及窄／宽屏布局。LG完整目录和实际导出文件核验仍有缺口。产品边界以 [SPEC.md](SPEC.md) 为准，精确差距与界面协作边界见 [HANDOFF.md](HANDOFF.md)。

一个面向上海陆家嘴中心 L+MALL 泰康大厦工作日午餐的手机优先静态网页。第一版不需要账号、后端或构建步骤，所有历史和设置都保存在当前浏览器中。

当前“说明”页公开随机机制、目录边界和共享目录与个人叠加层合成后的有效餐厅目录。页面不展示图片、地图或推荐菜；有来源时仅提供公开资料入口。DOM 展示与事件已集中在 `js/view.mjs`，业务 controller 和持久化位于 `js/app.mjs`，纯规则与数据契约位于 `js/core.mjs`。第一版暂缓反馈功能。

已确认的完整产品边界见 [SPEC.md](SPEC.md)。

## 本地运行

浏览器不能稳定地从 `file://` 地址读取默认 JSON，因此请在仓库目录启动任意静态文件服务器。例如：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。

## 验证

项目没有第三方运行时依赖。随机与数据规则使用 Node.js 内置测试运行器验证：

```powershell
node --test
node scripts/validate-restaurants.mjs
```

当前测试共36项，包含领域规则、controller 意图、迁移与备份失败保留原数据、目录更新后的个人数据保留，以及新增记录和个人管理流程。2026-09-08 实际通过；同日使用内置浏览器完成抽签、自由文字与显式关联、待入库、个人新增／隐藏恢复、忌口、备份无效文件／取消／恢复和刷新保留检查，并检查365×812及1280×900布局。确认操作使用网页内对话框，保留取消与确认；窄屏抽签自动滚动为底部导航留出空间。测试后已恢复空白个人状态。

内置浏览器点击导出后显示备份已生成，但自动化未收到下载事件，实际落盘文件尚未核验；导出内容的序列化由本地测试覆盖，不能将其等同于实际下载验收。

手工记录中输入名称后，只有点击候选才会关联正式餐厅；直接保存会保留输入原文，并可随后加入本地待入库。数据页可批量整理名称、维护个人随机池及设置忌口。共享目录更新不会自动改写既有记录，待入库名称始终不参与随机。

餐厅数据PR通过GitHub Actions运行同一个校验脚本，检查JSON可解析、唯一ID、名称／范围／文字位置和副范围1–8分钟步行时间，并复用运行时对可选字段的格式校验。检查通过不代表现实事实已经核实，仍需人工审核范围、营业与午间适用性；工作流不自动合并或部署。本轮仅运行本地校验，尚未在线运行Actions。

## 当前实现的数据

- 共享默认目录位于 `data/restaurants.json`；当前包含21家主范围和8家副范围餐厅。每次启动都读取部署版目录，再叠加当前浏览器的个人新增与隐藏项。2026-09-07补入陈香贵并修正首批LG来源，LG全集尚未核实，见 [本轮核查](data/lg-review-2026-09-07.md)。
- 参考人均和副范围步行时间是公开信息基础上的近似值，不是实时承诺；默认列表核验日期为 2026-08-27。
- 当前数据可以保留 `recommended_dishes`，但该字段可缺失，页面不展示，也不把它作为入库条件。
- 网页只导入导出一个 `lunch-picker-backup.json` 个人备份；它包含设置、忌口偏好、个人叠加层、待入库名称和历史，不复制或覆盖共享目录。
- 新状态写入 `lunch-picker.state.v2`。没有有效 v2 但存在有效 v1 时会迁移设置、历史和个人额外餐厅；旧 `lunch-picker.state.v1` 不会自动删除。
- 个人历史只存在浏览器本地；不要把个人导出文件提交到公开仓库。
