# 午餐随机选择器

> 开发状态（2026-09-01）：当前代码和已部署页面仍是 2026-08-27 的实现基线；用户已经确认下一版契约，但尚未实现。最新产品边界以 [SPEC.md](SPEC.md) 为准，已知实现差距和新对话接手顺序见 [HANDOFF.md](HANDOFF.md)。

一个面向上海陆家嘴中心 L+MALL 泰康大厦工作日午餐的手机优先静态网页。第一版不需要账号、后端或构建步骤，所有历史和设置都保存在当前浏览器中。

当前实现的“说明”页公开随机机制、白名单边界和当前浏览器使用的餐厅目录，并为每家店提供午餐建议、位置、地图和公开资料入口。下一版将按已确认契约移除图片、地图和推荐菜展示，重构共享目录、个人数据、忌口、手工记录与待入库，并把 DOM 展示层从业务 controller 中分离；第一版暂缓反馈功能。

已确认的完整产品边界见 [SPEC.md](SPEC.md)。

## 本地运行

浏览器不能稳定地从 `file://` 地址读取默认 JSON，因此请在仓库目录启动任意静态文件服务器。例如：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。

## 验证

项目没有第三方运行时依赖。随机与数据规则使用 Node.js 内置测试运行器验证：

```powershell
node --test
```

## 当前实现的数据

- 默认白名单位于 `data/restaurants.json`；首版包含 20 家主范围和 8 家副范围餐厅。
- 参考人均和副范围步行时间是公开信息基础上的近似值，不是实时承诺；默认列表核验日期为 2026-08-27。
- 当前数据仍包含 `recommended_dishes`，旧页面也会展示；下一版允许该字段缺失或保留，但第一版页面不展示，也不把它作为入库条件。
- 网页可导出 `restaurants.json` 或完整的 `lunch-picker-backup.json`，导入采用校验后整体替换，不会自动合并。
- 个人历史只存在浏览器本地；不要把个人导出文件提交到公开仓库。
